## Overview

A composite component containing everything you need to make fully accessibility form inputs using either the provided
`input` element or your own custom input.

<ViewSource path="components/Field" />

## Usage

```js
import { Field, useField } from '@strapi/design-system';
```

<Canvas of={FieldStories.Base} />

If you're using your own custom input not based off `Field.Input` then utilise the `useField` hook to gain access to the
following props:

```ts
interface Field {
  /**
   * @default false
   */
  error?: string | boolean;
  /**
   * @default null
   */
  hint?: React.ReactNode;
  /**
   * Shown at the end of the hint or error row, e.g. a character count.
   * @default null
   */
  counter?: React.ReactNode;
  id?: string;
  labelNode?: HTMLLabelElement;
  name?: string;
  /**
   * @default false
   */
  required?: boolean;
}
```

### With counter

`counter` renders at the end of the hint row, e.g. a character count, and stays at the end of the error row when the
error replaces the hint. It is sized to its content, so the message wraps beside it and never runs under it. Render
`Field.Hint` and `Field.Error` as usual: whichever of them is mounted shows the counter, and with neither of them there
is no counter.

The input is described by the hint or the error, then the counter. Screen readers read it on focus, not at every change,
so pass a text that reads well on its own, such as `12 of 60 characters` rather than `12/60`. Announcing every
keystroke with `aria-live` would be noise; if crossing a limit must be announced, do it from the input.

With a `counter`, `aria-describedby` lists several ids (`…-hint …-counter` or `…-error …-counter`): to find the input
described by an element, match one id with `[aria-describedby~="<id>"]`, not `=`.
